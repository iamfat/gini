# Spec Delta

## Purpose

约定框架全局错误处理器的升级策略：哪些错误级别升级为异常、哪些降级记录，以及 @ 抑制运算符的语义在 PHP 支持窗口（7.4 与 8.5）内保持一致。

## ADDED Requirements

### Requirement: 弃用通告不得升级为异常

全局错误处理器处于激活状态时，弃用级别通告（引擎产生的弃用通告与用户代码主动触发的用户弃用通告）MUST 被记录而不中断程序执行，MUST NOT 抛出异常。

#### Scenario: 引擎弃用通告继续执行

- **WHEN** PHP 运行时产生弃用级别通告（例如调用已弃用的运行时函数）且全局错误处理器已注册
- **THEN** 程序继续执行该语句之后的流程，不抛出未捕获异常

#### Scenario: 用户弃用通告继续执行

- **WHEN** 应用代码触发用户弃用通告（E_USER_DEPRECATED）
- **THEN** 程序继续执行，不抛出异常，通告信息进入低噪声日志通道

### Requirement: 抑制运算符语义跨版本一致

被 @ 抑制运算符屏蔽的错误，在支持窗口内的所有 PHP 版本上 MUST NOT 被全局错误处理器升级为异常或写入日志；判定 MUST 基于错误级别与当前错误报告掩码的按位比较，而非错误报告值为零的恒等比较。

#### Scenario: 被抑制的用户弃用通告静默

- **WHEN** 应用代码以 @ 抑制方式触发用户弃用通告
- **THEN** 在 PHP 7.4 与 PHP 8.5 下均不抛出异常，也不产生日志输出

### Requirement: 非弃用诊断错误仍须升级

处于处理器注册掩码内且未被 @ 抑制的非弃用诊断错误（如 E_USER_WARNING）MUST 继续升级为携带原错误信息、级别、文件与行号的异常。

#### Scenario: 用户警告升级为异常

- **WHEN** 应用代码未加抑制地触发 E_USER_WARNING 级别通告
- **THEN** 处理器抛出异常，异常消息与触发位置对应原始错误信息
